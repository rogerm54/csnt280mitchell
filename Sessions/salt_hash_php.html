Better passwords using salts and hashes

Using plain text for storing a password should never be done. Unfortunately, storing passwords in plain text is more common than it should be. Although this page is deprecated, it gives you an idea of how many sites use or used to use questionable password policies.

Salts and Hashes

A properly stored password should be salted and hashed. A salt is some text that is combined with a hash of the password. This combination is then hashed again, and that final hash is what is stored. The salt should be random. A hash is a special encoded form of a string. The key to a hash algorithm is that it generates a string of fixed length that is not reversible. That is, you cannot go in the reverse direction from the hash to obtain the orginal string.

Salts should be random

Salts should be random. That means that they should be some hard to guess text, that is different for each password. The salt should be generated each time a password is stored. A fixed salt is a bad idea, because once it is cracked, all the passwords can be cracked more easily. Tools such as John the Ripper can crack a set of passwords that use a fixed salt far more easily than if random salts are used.

Use appropriate hashes

In any popular database or web programming language, the SHA-512 hashing algorithm is available. This creates hash values consisting of 64 words. On Ubuntu Linux you can install the whois package, and this provides the mkpasswd tool. The mkpasswd tool can be used to generate SHA-512 hashes on the command line: 


$ mkpasswd -m sha-512 jane

$ mkpasswd -m sha-512 deoxyribonucleic_acid

As you can see, the sha-512 hash would not be work backwards to the original text. Unlike encryption, there is no one-to-one correspondence between the original text and the hashed text.

Using a salt

A salt is a string that is combined with the password string to make the password harder to guess. The salt should be randomly generated so that a different salt is used for each password. Here is a php function that builds on the do_hash() function to make use of a salt. 


   function do_hash($text) {
      return hash('sha512',$text);
   }
   function make_salt($text) {
      return do_hash(time() . $text);
   }

The now() function returns a string that corresponds to the current day and time. The || symbol is the concatenation operator in SQL. So, the salt is formed by taking the current date/time string, concatenating it with the passed string and then performing the sha-512 hash on the resulting string.

Creating a salted and hashed password

Next, we create a function for generating a salted and hashed password. 


   function do_hash($text) {
      return hash('sha512',$text);
   }
   function make_salt($text) {
      return do_hash(time() . $text);
   }
   function make_enc_pass($text, $salt) {
      return do_hash($text . $salt);
   }

The passed string is concatenated with the salt of the passed string. The resulting string is hashed again. This scheme makes it relatively difficult to guess the password, since the salt is random and unknown, and the amount and type of concatenations that are performed are also unknown.

Storing the password and salt

The following function could be used to store the password and salt into a table named users. It is also assumed that this table has the following fields: username, salt and enc_pass. 


   function add_user($fn, $ln, $e_mail, $pass) {
	  $pdo = connect();
	  if (!$pdo) {
		  return;
	  }
	  $sql = "insert into users (first_name, last_name, " .
	     "e_mail, salt, enc_pass) values (:fn, :ln, " .
	     ":e_mail, :salt, :enc_pass)";
	  $statement = $pdo->prepare($sql);
	  $myarray = array();
	  $myarray[':fn'] = $fn;
	  $myarray[':ln'] = $ln;
	  $myarray[':e_mail'] = $e_mail;
	  $myarray[':salt'] = make_salt($pass);
	  $salt = $myarray[':salt'];
	  $myarray[':enc_pass'] = make_enc_pass($pass, $salt);
	  $statement->execute($myarray);
   }

We need to store the salt along with the salted and hashed password, because the salt is required to check if the submitted username and password match. Let's create a php function that can be used to validate a username and password.

A function to validate the username/password

The check_id() php function will return the user's id if the username and password is valid. Otherwise, this function will return a -1. 


   function check_id($user, $pass) {
      $pdo = connect();
      if (!$pdo) {
		 return;
	  }
	  $sql = "select * from users where e_mail='$user'";
	  $results = $pdo->query($sql);
	  $count = $results->rowCount();
	  if ($count != 1) {
		 return -1;
	  }
	  else if ($count == 1) {
		 $row = $results->fetch(PDO::FETCH_ASSOC);
		 $salt = $row['salt'];
		 $enc_pass = $row['enc_pass'];
		 if (do_hash($pass . $salt) == $enc_pass) {
			return $row['id'];
		 }
		 else {
			return -2;
		 }
	  }
   }

Note that this function returns an integer as specified on line 3. Line 5 starts the declare block where local variables are declared. On line 6, the local variable, rec is defined to be of type "record". The "record" type is a record returned from a database select query.

Lines 8-17 form the definition of the check_id() function. On line 8 we attempt to select all fields into rec from the users table where the username field matches the submitted username. Lines 9-17 define the selection statements that handle the possible cases from this attempt.

The case going from line 9-14 is matched if the username is found in the users table. If this is true, the returned record is stored in the rec variable. Line 10 checks to see if the hash of the submitted password concatenated with the stored salt matches the stored password. If this is true the user's id is returned on line 11.

On lines 12-13, this is matched if the username is valid but the password is not. In this case a -1 is returned on line 13.

Lines 15-16 define the case that deals with the username not being in the users table. In that case, a -1 is returned on line 16.

Note that the check_id() function returns the same value (-1) for a bad username and a correct username with bad password. You may choose to return different values if you want to know the difference.

-- init.sql
drop table if exists users cascade;

  id serial,
  first_name varchar(30),
  last_name varchar(40),
  username varchar(50) unique,
  password text,
  salt text,
  enc_pass text,
  primary key (id)
